# 交接说明 — 开源桌面 AI Agent（基于 OpenClaw）

> 给接手实现的人/模型。**先读这份，再读同目录的 `README.md`（立项判断与理由）。**
>
> 本文里的"已验证"部分是 2026-09 在 Linux 容器里实测 OpenClaw `2026.6.34` 得到的，
> 不要重新推测，也不要相信训练数据里的旧信息——这个项目里有好几处，

## 0. 一句话任务

把 OpenClaw 封装成一个**双击安装、不用开终端**的桌面应用，开源。

---

## 1. 已验证的事实（不要重新调研，直接用）

| 事实 | 来源 | 为什么关键 |
|---|---|---|
| OpenClaw 是 **MIT 协议** | 官方 | 可以合法封装、修改、再分发 |
| 当前版本 `2026.6.34` | `openclaw --version` 实测 | — |
| `npm install -g openclaw` 实测 **18 秒 / 296 个包** | 实测 | 安装本身不慢，慢的是前置条件 |
| 要求 Node 22.22.3+ / 24.15+ / 25.9+，Windows 需 WSL 2 | 官方文档 | 这是最大的一道门槛 |
| 配置文件在 `~/.openclaw/openclaw.json` | `openclaw setup` 输出 | 所有自动化的落点 |
| 默认模型 `gpt-5.6-sol`，无 Key 无法推理 | `openclaw status` 实测 | — |
| 记忆检索默认用 `openai`，需要**单独的** `OPENAI_API_KEY` | `openclaw doctor` 实测 | 容易漏，会导致"装好了但半残" |
| **网关鉴权可完全脚本化** | 实测已验证 | 见下方 §2，这是整个方案能成立的关键 |
| 多个内置技能依赖 `ffmpeg` / `jq` / `summarize` / `xurl`，官方给的安装方式是 brew | `openclaw doctor` 实测 | Windows 用户无解，必须内置或默认关闭 |
| CLI 有 **50+ 个顶层命令** | `openclaw --help` 实测 | 概念负担本身就是流失点 |

### ⚠️ 最容易搞错的一条

**Anthropic 已于 2026-01 关闭 OAuth 通道，2026-04-04 停止向所有第三方工具供给订阅额度。**

意味着：**Claude Pro / Max 订阅不能给 OpenClaw 用**，只能走按量计费的 API Key。

所以 EasyClaw 宣传的「零配置」是**猎豹在垫推理成本**，不是封装技巧。
开源项目做不到这一点。

**不要把「零配置」写进目标。** 目标是「**一个安装包 + 一个输入框**」。
任何声称能绕过 API Key 的方案都是错的，别浪费时间。

## 2. 已验证可行的关键技术点

网关鉴权这一层可以做到用户完全无感，实测通过：

```bash
TOKEN=$(openssl rand -hex 24)
openclaw config set gateway.auth.token "$TOKEN"
openclaw status --token "$TOKEN"     # 正常返回状态表，无需任何用户输入
```

**这是整个方案成立的支点**——它证明了「装完直接能用」不是幻想。
实现时：首次启动自动生成 token，写入配置，同时存进系统钥匙串
（macOS Keychain / Windows Credential Manager），用户全程不知道有这回事。

## 3. 已定的架构决策（连同理由，不同意请先反驳理由）

| 决策 | 理由 |
|---|---|
| **目标用户 = 懂一点但不想折腾的人**（开发者、极客、注重隐私的知识工作者），不是纯小白 | 纯小白拼不过有补贴的闭源产品；这批人才是开源项目能长起来的土壤 |
| **自带 Key 与 Ollama 本地模型并列为两条一等路径** | 选择权本身就是开源版该给的东西；Ollama 是唯一真正无 Key 的路 |
| **不预留云端接口，数据不出本机** | 「数据不出本机」是差异化本身，留了口子这个承诺就稀释了 |
| **Tauri 而非 Electron** | 安装包体积小一个数量级。「安装包 300MB」对一个主打"装起来不烦"的产品是自相矛盾的 |
| **不自研 Agent 内核** | OpenClaw 是 MIT，直接用。价值在封装层，不在重造轮子 |
| **保留逃生舱口**：GUI 里能看到并直接打开原始配置文件 | 目标用户会想知道底下发生了什么；藏死了反而失去信任 |

**产品名未定。明确不要用 `Easy Claw`**——那是猎豹移动的在售产品，
同平台同品类，域名商标已被占。也建议避开整个 `Claw` 词族：
现在用等于给 OpenClaw 的热度做背书，热度退潮后名字会从资产变成负债。

## 4. v1 范围

### 要做

1. **环境自举**：检测/内置 Node 运行时与 OpenClaw，首次启动自动跑 `openclaw setup`（幂等）
2. **网关 token 自动生成**（见 §2），存系统钥匙串
3. **首启向导**，两条并列路径：
   - **自带 Key**：一键深链到厂商 Key 页面 → 粘贴 → **发一个最小真实请求验证** → 当场告知成功/失败及失败原因 → 存钥匙串
   - **Ollama**：检测本地是否安装 → 列出已有模型 → 选一个。**诚实标注代价**（7B 需 16GB 内存，70B 需 48GB，效果明显弱于云端）
4. **进程托管**：桌面 App 自己拉起并守护 gateway 子进程。**不要依赖 systemd/launchd**
5. **托盘常驻** + 启停 + 状态 + 日志查看
6. **GUI 扫码接入 1 个聊天渠道**（选 Telegram，接入成本最低）
7. **权限面板**：明确列出它能访问哪些目录、能执行什么命令
8. 内置常用外部依赖（至少 `ffmpeg`、`jq`），其余依赖外部二进制的技能**默认关闭**

### 明确不做

手机端 · 自研模型服务 · 云端同步 · 账号体系 · 插件市场 · 团队/企业版 · 一次性接入全部渠道

## 5. 验收标准

**拿这个卡，别拿感觉卡：**

> 找 5 个没用过 OpenClaw 的人，从下载安装包到「在 Telegram 里给它发一条消息并收到回复」，
> **中位数 ≤ 10 分钟，且全程不需要打开终端。**

做不到就不叫 easy，别上线。

补充硬性项：
- 安装包必须**签名**（macOS 公证 / Windows 代码签名）。未签名会弹安全警告，
  对一个主打"省心"的产品是致命自相矛盾
- 卸载要干净（含 `~/.openclaw` 的处理要询问用户，别默认删他的会话记录）

## 6. 最大的风险：提示词注入

一个**连着聊天软件、又能执行本机命令**的 Agent 是天然靶子：
陌生人发一条消息 → 模型读到 → 模型执行 → 用户的电脑被操作。

这个项目里尤其严重：主打易用意味着用户群包含**判断不了这个风险的人**；
开源意味着攻击者能读全部代码精确构造绕过；出事故没有公关团队接得住。

**必做**（这些同时也是闭源竞品给不了的卖点）：
- 默认只读，执行类操作需要**显式批准**
- 目录白名单
- 危险操作二次确认
- 所有 Agent 行为留**可审计日志**，GUI 里能直接看

OpenClaw 自带 `sandbox` / `exec-policy` / `approvals` 三组命令，
**先去把它们的真实行为摸清楚再动手，不要重新发明。**

## 7. 给接手者的方法建议

这份文档里最值钱的部分不是结论，是**结论的来源**——
它们全部来自「真的把 OpenClaw 装一遍、跑一遍、看它报什么错」，
而不是根据文档推测。

建议接手后第一件事也这么做：

```bash
npm install -g openclaw
openclaw setup
openclaw doctor          # 这条会一次性吐出所有缺失项，是最高信息密度的一步
openclaw --help          # 感受一下 50+ 命令的概念负担
```

跑完你会对"要消灭什么"有具体的体感，比读十遍这份文档管用。

另外注意：本文的实测是在 **Linux 容器**里做的。
**macOS/Windows 的打包与签名链路、聊天渠道扫码登录、真实模型调用都未实测**，
这三块要自己验证，别假设。
