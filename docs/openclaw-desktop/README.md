# 开源版桌面 AI Agent（基于 OpenClaw）— 立项判断

> 目标：做一个 EasyClaw 那样的桌面智能体，底层用 OpenClaw，开源。
> 本文回答一件事：**这个项目能不能做，以及做成什么样才立得住。**
>
> 文中的摩擦数据是 2026-08 在 Linux 容器里实测 OpenClaw `2026.6.34` 得到的，
> 标注了哪些是实测、哪些是推断。

---

## 一、先说那个会毁掉立项的事实

EasyClaw 的核心宣传是「**不用配 API Key，三分钟上手**」。

但 OpenClaw 现在必须有 API Key 才能跑：

- 2026 年 1 月，Anthropic 关掉了 OAuth 通道
- 2026 年 4 月 4 日，订阅额度对所有第三方工具停止供给

也就是说 Claude Pro / Max 的订阅额度**不能**给 OpenClaw 用，只能走按量计费的 API Key。

**所以 EasyClaw 的「零配置」不是一个封装成就，是一个商业模式成就。** 它能做到不问用户要 Key，
只可能是因为猎豹自己垫付了推理成本，或者把请求路由到了自家/廉价模型（他们还有个国内版叫「元气 AI Bot」）。

**这一条对你的意义：开源项目没有人替用户付这张账单。**
你可以把安装做到双击，但你消灭不掉「用户得自己搞一个 Key」这一步——除非你自己出钱，
那就不是开源项目了，是一门要融资的生意。

**结论：把「零配置」从你的目标里划掉。它不是你努力就能达到的，它是资本量决定的。**
下面讲你实际能拿下什么。

## 二、实测：首次运行到底卡在哪

在干净环境里从零跑一遍 OpenClaw，非技术用户会依次撞到 9 层墙：

| # | 摩擦 | 实测到的具体表现 | 开源工程能否消灭 |
|---|---|---|---|
| 1 | Node 运行时 | 需要 Node 22.22.3+ / 24.15+ / 25.9+ | ✅ 打包内置运行时 |
| 2 | Windows 需要 WSL 2 | 官方要求 | ✅ 打包时绕开 |
| 3 | 命令行安装 | `npm install -g openclaw`（实测 18s / 296 个包） | ✅ 换成安装包 |
| 4 | 初始化命令 | `openclaw setup` 才会生成配置与工作区 | ✅ 首次启动自动执行 |
| 5 | **网关鉴权** | 直接查状态会报 `GatewayCredentialsRequiredError` | ✅ **已验证**：随机生成 token 写入配置即可，全程无需用户参与 |
| 6 | 服务托管 | 需要 systemd / launchd 托管常驻进程 | ✅ 桌面 App 自己就是宿主，子进程拉起即可 |
| 7 | 外部二进制依赖 | 多个技能要 `ffmpeg` / `jq` / `summarize` / `xurl`，官方给的安装方式是 brew | ✅ 内置常用的，其余默认关闭 |
| 8 | 概念面太宽 | CLI 有 50+ 个顶层命令：gateway / workspace / channels / nodes / pairing / sandbox / exec-policy / secrets / plugins / skills / mcp… | ✅ GUI 只暴露 3 个概念 |
| 9 | **API Key** | 默认模型 `gpt-5.6-sol`，无 Key 无法推理；记忆检索还要单独的 `OPENAI_API_KEY` | ❌ **消灭不掉** |

**9 层里有 8 层是纯工程问题，开源完全能解决。只有第 9 层不行。**

这个结论比预想的乐观得多：真正的护城河（钱）只挡住了一层，剩下八层挡住普通用户的东西，
全都是可以靠打包和 GUI 拆掉的。

> 实测边界说明：以上在 Linux 容器内验证。第 6 项在容器里表现为
> 「systemd user services unavailable」，真实桌面环境有 launchd/systemd，
> 但结论不变——桌面 App 本来就该自己管子进程，不该依赖系统服务。
> Windows/macOS 的打包链路、渠道扫码登录、真实模型调用均未实测。

## 三、那唯一消灭不掉的一层，怎么处理

不要假装它不存在，把它做成**一个输入框 + 60 秒引导**：

1. 首启界面直接深链到模型厂商的 Key 页面（一次点击打开浏览器）
2. 用户复制粘贴进来
3. 立刻发一个最小请求验证，当场告诉他成功还是失败、失败为什么
4. 存进系统钥匙串（macOS Keychain / Windows Credential Manager），不落明文配置

**同时提供一条真正无 Key 的路径：默认支持 Ollama 本地模型。**
诚实标注代价——7B 级别要 16GB 内存，70B 级别要 48GB，效果明显弱于云端模型。
它不该是主推路径，但它让「我完全不想给任何人钱」的用户有得用，
而这恰好是开源项目最核心的那批用户。

**承诺要写成做得到的样子：不是「零配置」，是「一个安装包 + 一个输入框」。**

## 四、你的差异化不是「更简单」

正面拼易用性你打不过——对方有钱补贴推理成本，你没有。

但换个角度：**这是一个能控制你电脑、读你文件、连你聊天账号的东西。**

EasyClaw 是闭源二进制，用户必须信任猎豹的服务器不看他的 prompt 和文件。
对这类权限的软件来说，**开源可审计 + 数据不出本机 + 不锁供应商**不是「更差的同一件事」，
是一个**根本不同的价值主张**。

定位建议：

> 不是「更简单的 EasyClaw」，而是「**你能自己看懂、自己审计、自己换模型的桌面 Agent**」。

这条路的用户画像也不同：他们不是完全的小白，是**懂一点、但不想折腾**的人——
开发者、运维、极客、注重隐私的知识工作者。这批人恰好也是开源项目能真正长出来的土壤。

## 五、v1 做什么

**一句话范围：把上面第 1–8 层摩擦全部消灭，第 9 层做成 60 秒引导。别的都不做。**

| 做 | 不做 |
|---|---|
| 签名的一键安装包（macOS / Windows） | 手机端 |
| 内置 Node 运行时 + OpenClaw | 自研 Agent 内核（OpenClaw 是 MIT，直接用） |
| 首启向导：Key 引导 → 验证 → 存钥匙串 | 自己的模型服务 |
| 自动生成网关 token（已验证可行） | 云端同步 / 账号体系 |
| 托盘常驻 + 启停 + 日志查看 | 插件市场 |
| GUI 扫码接入 1 个聊天渠道（选 Telegram，最好接） | 一次性接入全部渠道 |
| Ollama 本地模型开箱可选 | 团队/企业版 |
| 权限面板：明确列出它能碰哪些目录、能执行什么 | |

**技术选型建议：Tauri 而不是 Electron。** 安装包体积小一个数量级，
而「安装包 300MB」对一个主打「装起来不烦」的产品是自相矛盾的。

**验收标准（拿这个卡自己，别拿感觉卡）**：
找 5 个没用过 OpenClaw 的人，从下载到「在 Telegram 里给它发一条消息并收到回复」，
**中位数 ≤ 10 分钟，且全程不需要打开终端**。做不到就不叫 easy。

## 六、最大的风险是安全，不是技术

一个连着聊天软件、又能执行本机命令的 Agent，天然是**提示词注入的靶子**：
别人给你发一条消息 → 模型读到 → 模型执行 → 你的电脑被人操作了。

这件事在这个项目里特别严重，因为：

- 你主打易用，用户群会包含**判断不了这个风险的人**
- 开源意味着攻击者能读你的全部代码，精确构造绕过
- 出一次事故，开源项目没有公关团队接得住

**但这同时是你最好的差异化机会。** 认真做权限模型——
默认只读、执行需要显式批准、白名单目录、危险操作二次确认、
所有 Agent 行为留可审计日志——这些做扎实了，
「我敢把它装在我主力机上」本身就是一个卖点，而且是闭源产品给不了的。

OpenClaw 自己有 `sandbox` / `exec-policy` / `approvals` 这几组命令，
说明底层已经有相关机制，v1 的工作是**把它们用对、并在 GUI 里让用户看得懂**，
而不是重新发明。

## 七、名字

**不要叫 Easy Claw。** 那是猎豹移动的在售产品，同平台同品类，域名商标都已被占，
拿来用等于主动招律师函，搜索流量也一点吃不到。

更进一步：**整个 Claw 词族现在都在给 OpenClaw 的浪做背书。**
热度退潮之后，`X-Claw` 这种名字会从资产变成负债——
三年后别人看到只会想起「哦，蹭 OpenClaw 那波的」。

原来的 `QmiRun` 有个别人拿不走的优点：**独一无二、搜索零冲突**。
它的问题只有一个——没人知道怎么念。**换名字要同时解决「能念」和「唯一」，
只解决一个不叫升级。**

## 八、下一步

立项前先答三个问题，这三个的答案会显著改变要写的代码：

1. **目标用户到底是谁？** 完全的小白，还是「懂一点但不想折腾」的人？
   这决定 GUI 藏多少东西、以及要不要保留逃生舱口（高级用户直通配置文件）。
2. **主推哪条模型路径？** 自带 Key（能力强、要花钱）还是 Ollama 本地（免费、弱）？
   这决定首启向导的主干流程长什么样。
3. **你打算靠什么长期活着？** 纯爱发电、开放内核 + 付费托管、还是先做出来再说？
   这决定架构里要不要预留云端接口——事后补比一开始留贵得多。
